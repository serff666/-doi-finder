# DOI Finder

在自己电脑上运行的文献检索、DOI 解析与 PDF 批量下载工具。界面是浏览器里的一个本地网页，没有账号体系。

它做三件事，并且对每一条结果说明依据或失败原因：

1. **找文献**：从标题、参考文献、主题、作者、ORCID、期刊或课题组页面得到一份文献清单；
2. **解析 DOI**：把标题或整条参考文献对应到 DOI，并标明匹配的可信程度；
3. **下载并整理**：按出版社和发表年份选择下载路线取得 PDF，按统一规则存进你指定的工作区。

> English: [README.en.md](README.en.md)　·　Linux 说明：[README.linux.md](README.linux.md)　·　变更记录：[CHANGES.md](CHANGES.md)

> **声明**
> 本项目仅用于学术研究与学习交流，不用于商业盈利；作者不提供、不出售任何文献内容。
> 程序可以连接第三方来源，其中包括 Sci-Hub 镜像。这类来源是否合法取决于你所在的国家/地区和所在机构的规定，**是否使用、如何使用由使用者自行判断并承担全部责任**。Sci-Hub 兜底默认开启，可在设置里关闭。
> 请遵守各出版社的服务条款与著作权法；下载的文献仅供个人研究，请勿再分发。

## 1. 它能做什么，不能做什么

**能做**

- 批量把标题 / 参考文献 / BibTeX / RIS 解析成 DOI，每条给出匹配依据；
- 批量按 DOI 下载 PDF，每条记录实际来源渠道，失败时记录原因；
- 从主题、作者、期刊、课题组网页、ResearchGate 作者页、ChemASAP 等入口取得文献清单，并就地下载；
- 重复运行不会重复下载：已下载的文献记录在工作区的 `.doi-index.json` 里。

**不能保证**

- **不保证每篇都能下到**。能否取得全文取决于该文是否开放获取、你所在机构是否订阅、出版社是否拦截自动访问，以及第三方来源当时是否可用。没有下到的会明确标出原因。
- **不保证 DOI 解析百分之百正确**。程序用多项证据给出可信度分档，低档结果需要你自己核对。
- **不绕过付费墙**。订阅文章只能靠你自己的机构登录会话（见 §6）或你自行选择启用的第三方来源取得。

## 2. 安装与启动

**Windows 安装包**（发布页的 `DOI-Finder-Setup-<版本>.exe`）：单文件安装程序，默认装到 `%LOCALAPPDATA%\Programs\DOI Finder`，不需要管理员权限，可在控制面板卸载。安装包没有代码签名，Windows SmartScreen 可能提示，选择「更多信息 → 仍要运行」。启动后程序会用本机的 Chrome 或 Edge 打开一个独立的应用窗口；本机没有这两种浏览器时，改用系统默认浏览器。

**从源码运行**（需要 Python 3.11 或更高）：

```bat
:: Windows
python server.py --open            :: --open 表示启动后打开界面；run_server.cmd 等价于此
```

```bash
# Linux / macOS
./run.sh                           # 第一次运行会在项目目录创建 .venv 并安装依赖
```

- 服务只监听 `127.0.0.1`，默认端口 8765；被占用时依次尝试后面的端口（最多 40 个）。用环境变量 `DOIFINDER_PORT` 可指定端口，`DOIFINDER_NO_BROWSER=1` 可禁止自动打开界面。程序没有 `--port` 参数。
- 界面里点右上角「退出」会停止服务。
- 可选依赖（`requirements.txt`）：`openpyxl`（导出 Excel）、`pypdf`（归档时从 PDF 首页猜标题和年份）。没有它们，对应功能不可用，其余功能不受影响。
- 文件夹 / 文件选择对话框使用 Python 自带的 tkinter，没有备用实现。tkinter 不可用时，点「选择…」会报错，此时直接在输入框里填路径。
- 机构通道和部分下载步骤需要本机装有 Chrome 或 Edge。

**验证情况**：自动化测试（单元测试、期刊端到端流程、浏览器端界面检查）在 GitHub Actions 的 Windows 和 Ubuntu、Python 3.11 / 3.13 上运行。真实出版社流量、机构登录、各第三方来源的可用性，没有自动化覆盖，只能靠实际使用验证；Linux 只在源码层面测过，macOS 没有测试。

## 3. 第一次使用

打开界面后先设置两项，其余可以以后再改：

| 位置 | 内容 | 说明 |
|---|---|---|
| 顶部「工作区」 | 一个根文件夹，例如 `D:\文献` | 所有页面下载的文件都放在它下面。默认是 `~/Downloads/DOI Finder`（Windows 下即 `C:\Users\<你>\Downloads\DOI Finder`） |
| 设置里的「联系邮箱」 | 你自己的邮箱 | 会随请求发给 Crossref、OpenAlex、Unpaywall 等服务（这些服务对带邮箱的请求限流更宽松）。可以不填，但被限流（HTTP 429）的概率更高 |

之后的典型流程：在「① 标题 → DOI」粘贴标题，点「开始批量检索」，核对状态；再点「→ 下载这些 PDF」，在本页看进度；下载完成后点「打开下载目录」。

| 页面 | 输入 | 输出 |

| ② DOI → PDF | 一批 DOI | 本地 PDF，附每条的来源或失败原因 |
| ③ 主题搜索 | 关键词，可加作者、ORCID、年份、「仅开放获取」 | 文献列表，勾选后在本页下载 |

| ⑤ 期刊追新 | 期刊名或 ISSN | 该刊近期文章，标出上次刷新之后新增的 |
| ⑥ ResearchGate | 作者主页链接 | 该作者页面上的论文清单（需先在弹出的窗口里登录并通过人机验证） |
| ⑦ 归档 | 本地已有的 PDF | 按命名模板改名并放进工作区 |
| ⑧ 网页文献 | 课题组 publications 页面地址 | 页面上出现的论文标题、DOI、PDF 直链 |

## 5. 标题 → DOI：怎么判断“对不对”

**输入**：一行一条标题；整条参考文献；带序号的列表（`1.`、`2)`、`(3)`、`[4]`、`#5` 会被去掉）；BibTeX；RIS。行尾带 `doi: 10.xxxx/…` 的直接采用，不再查询。

**查询来源**：以 Crossref 为主；Crossref 没有可用结果时，可用 OpenAlex 补查（开关「Crossref 不足时用 OpenAlex 兜底」，默认开）。「相同标题只查询一次」会合并重复标题。

**打分**：以标题相似度为基础。输入里带有年份、第一作者、期刊或卷期页时，会与候选逐项核对：

- 只有明确的矛盾才扣分：年份相差 2 年及以上，或第一作者与候选的所有作者都对不上，状态降一级并在备注写明；输入里没有的字段不扣分；
- 年份和第一作者都吻合，且标题相似度不低于 0.70 的「需核对」，升为「可能匹配」；
- 同一标题的预印本与正式版并存时，按年份选更吻合的，另一个留在备选里。

**结果状态**

| 状态 | 含义 | 建议 |
|---|---|---|
| 高可信 | 标题高度一致，其余证据没有矛盾 | 可直接使用 |
| 可能匹配 | 标题接近，但证据不足 | 看一眼 DOI 链接 |
| 需核对 | 找到候选，但字段有出入 | 点「修改」确认或手填 |
| 未找到 | 没有可用候选 | 手填，或换到 ③ 主题搜索 |
| 检索失败 | 查询本身没成功（网络、限流等） | 重试，与「未找到」不是一回事 |
| 已提供 / 人工确认 | 输入自带 DOI / 你手动确认过 | — |

**导出**：Excel、Markdown、HTML、CSV、纯文本 DOI 清单；参考文献格式有 GB/T 7714、ACS、APA 三种，由 Crossref 元数据生成，缺失的字段留空，不做推测。

**中文文献**：知网、万方的论文在 Crossref 里常常没有 DOI。把百度学术的论文链接粘进「百度学术链接 → DOI」，程序会取回标题、DOI、期刊、卷期页。

## 6. DOI → PDF：下载路线怎么定

### 6.1 路线由什么决定

程序先按 DOI 前缀判断出版社类别，再结合**发表年份**（2021 年之后或年份未知，视为较新）和你的设置，生成一个有顺序的步骤列表，依次尝试，第一个拿到有效文件的步骤结束该篇。步骤含义：

| 步骤 | 做什么 |
|---|---|
| `Sci-Hub` | 依次尝试 Sci-Hub 镜像（按历史成功率排序）和 Sci-Net；遇到 ALTCHA 挑战时自动求解 |
| `API` | Elsevier / Wiley 的官方接口，需要你自己的 key / token（见 §8） |
| `开放获取` | 见 §6.3 |
| `PMC` | PubMed Central 全文 |
| `机构浏览器` | 用本机 Chrome/Edge 里你自己登录过的会话取 PDF（见 §6.4） |

**Sci-Hub 开启时，对所有 DOI 都排在第一位**，其后才是下表的顺序；关闭后直接从下表开始。

| DOI 类别 | 顺序（未列出的步骤不参与） |
|---|---|
| 预印本（arXiv、ChemRxiv、bioRxiv/medRxiv、Research Square、SSRN、Preprints.org） | 开放获取 →（启用机构通道时）机构浏览器 |
| 全开放出版社（PLOS、Frontiers、MDPI、eLife、Copernicus、BMC、Scientific Reports） | 开放获取 → PMC |
| Elsevier（10.1016）、Wiley（10.1002） | API（有 key 时）→ 开放获取 →（较新且启用机构通道）机构浏览器 → PMC →（启用机构通道）机构浏览器 |
| 订阅刊：ACS、RSC、AIP、Science、Springer / Springer Nature、Taylor & Francis、SAGE、IOP、Oxford、ECS、Liebert | 机构浏览器 → 开放获取 → PMC（年份不改变这一类的顺序） |
| 其它 | 开放获取 → PMC →（启用机构通道）机构浏览器 |

另外两条规则：

- **预印本提前**：发表于 2025 年及以后的文献，在机构浏览器之前先试预印本，但只用「期刊记录里明确登记了对应预印本」的那一篇；设置里和每页的「新文献先预印本」可关闭。
- **预印本兜底**：所有路线都失败后，最后再试一次预印本（见 §6.5）。

每篇文献的总时间预算是 240 秒，超出后不再启动新的来源；最后的预印本兜底不受这个限制，只受「停止」按钮影响。

### 6.2 命名与重复

- 文件名模板默认 `{first_author}_{year}_{title}`，可用占位符 `{first_author}` `{year}` `{title}` `{journal}` `{doi}`。标题和作者会截断，非法字符会替换，同名自动加序号（勾「重新下载」才覆盖）。
- 工作区根目录的 `.doi-index.json` 记录已下载的 DOI。再次出现同一 DOI 时，已下载的跳过；如果它已在另一个文件夹里，则复制过去，不再联网。旧版本在各子文件夹里留下的索引会被自动识别。
- 拿到的内容不是 PDF 而是结构化全文（XML/HTML）时，文件扩展名会如实写成 `.xml` / `.txt`，不会伪装成 PDF。

### 6.3 开放获取这一步

1. 对 arXiv、bioRxiv、eLife 这类能直接构造链接的来源，不发请求就得到候选链接；
2. 同时向 OpenAlex、Unpaywall、Europe PMC、Semantic Scholar、PubMed Central、OSTI、Zenodo、HAL、Crossref、DOAJ、CORE（需免费 key，可选）、Internet Archive Scholar、Elsevier 开放获取接口、IEEE 查询候选链接，共用 25 秒的截止时间，超时的来源被丢弃；
3. 候选链接去重后排序（已知的镜像站和直链靠前），再**逐个**尝试前 8 个，取第一个拿到有效 PDF 的；
4. 纯 HTTP 都失败、且本机有 Chrome/Edge 时，会在真实浏览器里打开该文献的 DOI 页面再试一次（很多开放获取文章的落地页有脚本挑战）。

查询结果缓存：有结果的缓存 24 小时，空结果缓存 6 小时。

“拿到有效 PDF”的判据是文件开头出现 `%PDF`。**例外**：从课题组网页（⑧）下载的 PDF 直链，还会检查文件结尾标记，截断的文件会重下；其它渠道目前只检查文件头，不检查是否完整。

### 6.4 机构通道（可选）

- 原理：程序用本机 Chrome/Edge 打开出版社页面，复用你在该浏览器配置里登录过的校园网、CARSI 等会话取 PDF。程序不读取、不保存你的密码；登录状态存放在 `%LOCALAPPDATA%\DOIFinder\browser-profile*`。
- 第一次使用，在下载页点某一行的「机构登录」，在弹出的窗口里登录一次；会话过期后再登录一次。
- 设置项 `inst_enable` 默认开启，但前提是本机找得到 Chrome 或 Edge。关闭后上表中所有“机构浏览器”步骤都不执行。
- 程序不会因为“推测你没有订阅”就跳过这一步：期刊可能是开放获取。但在上表里没有列出机构浏览器的类别（全开放出版社），也不会使用它。
- 机构通道是**串行**的，每篇之间至少间隔 3 秒。短时间内大量下载可能被出版社判定为系统性下载而封禁整个机构的访问，几百篇以上请分批运行。

### 6.5 预印本

正式版下不到时，作者常把同一篇放在 ChemRxiv，而预印本的标题和 DOI 往往与正式版不同，不能直接按 DOI 对应。程序的做法：

1. 先看期刊记录里登记的预印本关系（Crossref 的 `has-preprint`）；
2. 否则用 ChemRxiv 官方搜索和 Crossref 里 ChemRxiv 的记录（DOI 前缀 10.26434），按标题相似度、第一作者、年份打分；
3. 候选分为「确定 / 很可能 / 可能」，并写出匹配依据。自动下载只采用「确定」和「很可能」，「可能」只在 ⑩ 页由你手动勾选；
4. 下到的预印本在说明里标明是预印本，**内容可能与正式发表版有出入**。

另外：遇到 SSRN、Research Square 这类预印本 DOI，程序会用标题回 Crossref 找正式发表版，找到就改下正式版。

「查询失败」表示没有问成功，不等于该文没有预印本，可以重试。

## 7. 文件怎么存

所有页面用同一规则，路径永远是：

```
工作区 / 文件夹 / 分层 / 文件.pdf
例：D:\文献\Zhang Xinglong\2025\Zhang_2025_Title.pdf
```

- **工作区**：顶部设置的根目录。页面里可以给这一页单独指定另一个工作区。
- **文件夹**：第一层，按“你在收集什么”自动建议，可在页面里改名。建议名随界面语言变化（中文界面下是下表里的中文名，英文界面下是对应的英文名）。
- **分层**：不分层 / 按年份 / 按期刊 / 按期刊 → 年份 / 按年份 → 卷期。年份和期刊来自文献元数据，缺失时放进「年份未知」「期刊未知」（这两个文件夹名由程序写入，不随界面语言变化），不会丢文件。
- 每个页面的下载设置行显示「将保存到：…」，下载前可以看到完整路径。

| 页面 | 自动建议的文件夹 | 自动建议的分层 |
|---|---|---|
| ③ 主题搜索（填了作者） | 作者名 | 按年份 |
| ③ 主题搜索（只有关键词） | 关键词 | 不分层 |
| ⑥ ResearchGate | 该作者的名字 | 按年份 |
| ⑤ 期刊追新 | 期刊名 | 按年份 |
| ⑨ 期刊文库 | 期刊名 | 年份 → `Volume V, Issue I` |
| ⑧ 网页文献 | 课题组网站域名 | 按年份 |
| ④ ChemASAP | `ChemASAP` | 按期刊 |
| ⑩ 预印本 | `预印本` | 不分层 |
| ① 标题 → DOI、② DOI → PDF | `未分类` | 不分层 |

## 8. 设置与密钥

设置保存在 `%LOCALAPPDATA%\DOIFinder\settings.json`（Linux：`~/.local/share/DOIFinder`）。仓库里的 `settings.example.json` 是字段示例，不含任何密钥。

| 设置 | 默认 | 说明 |
|---|---|---|
| 并发数 | 3，范围 1–5 | 同时下载几篇。过高容易被出版社限流 |
| Sci-Hub / Sci-Net 兜底 | 开 | 见 §6.1；可关闭 |
| 跳过 Sci-Hub 镜像证书校验 | 关 | 仅当镜像证书过期而无法连接时才开，且只应在可信网络下使用 |
| 机构通道 | 开（需要 Chrome/Edge） | 见 §6.4 |
| 新文献先预印本 | 开 | 见 §6.1 |
| Elsevier API key / insttoken | 空 | 在 dev.elsevier.com 免费申请；订阅全文还需机构给的 insttoken。没有 key 时，Elsevier 文章在失败说明里会提示填写 |
| Wiley TDM token | 空 | 在 Wiley 在线图书馆的 TDM 页面获取 |
| OpenAlex key、CORE key | 空 | 可选，提高配额 |
| 命名模板 | `{first_author}_{year}_{title}` | 见 §6.2 |

Elsevier key 与 Wiley token 是发给个人账号的，**不要共享**。

## 9. 其它页面的补充说明

- **③ 主题搜索**：关键词检索用 OpenAlex（默认最多返回 40 条），结果表显示标题与 DOI、期刊与年份、作者、被引数、是否开放获取；填了 ORCID 时，先用 ORCID 公开接口取该作者登记的作品，取不到再经 OpenAlex。
- **④ ChemASAP**：数据来自第三方服务 ChemASAP（`api.baranlab.org`），收录哪些期刊由该服务决定，本程序不控制，也没有按期刊或学科勾选的控件；本页可按标题、作者、期刊名筛选，或只看开放获取。数据缓存 10 分钟。
- **⑤ 期刊追新**：数据来自 Crossref 的期刊目录，不经过出版社网页。「新」标记表示上次刷新之后新出现的；「标记已读」保存当前进度。
- **⑥ ResearchGate**：该站有 Cloudflare 人机验证，必须先点「打开并登录」在弹出的窗口里通过。抓取逐页翻，几百篇需要一两分钟。抓到的条目可能没有 DOI，此时走标题解析。
- **⑦ 归档**：读取 PDF 首页文字猜标题和年份（需要 `pypdf`），也可手动填写标题、作者、年份、期刊、DOI。
- **⑧ 网页文献**：用真实浏览器打开页面并逐轮加载（有的页面要滚到底），可能需要一两分钟。页面给了 PDF 直链的直接从链接下载；只有 DOI 的走 §6 的路线；只有标题的需要送去 ① 解析。arXiv 论文没有 DOI 时，用 `10.48550/arXiv.<编号>` 合成。文件名带标题和链接哈希，避免重名覆盖。
- **⑨ 期刊文库**：书目来自 Crossref，目录页、封面、勘误等会按「类型」选项过滤（默认排除更正、社论、目录）。可选显示审稿周期和分区，见下节。

### 期刊信息（可选）

⑨ 页可以显示一本期刊的平均 / 中位审稿周期、JCR 分区、中科院分区和影响因子。数据来自公开数据集 [CrushSCI-Journal-Review-Time](https://github.com/wangshunqi2020-commits/CrushSCI-Journal-Review-Time)（CC BY-NC 4.0：仅限非商业使用，需署名）。**本项目不内置这份数据**，点「下载期刊数据」后只保存在你自己的电脑上。审稿天数是收稿到录用的日历天数，只是该数据集里观察到的样本，不代表任何保证。

## 10. 隐私与数据流向

- 程序和数据都在你的电脑上运行；服务只监听 `127.0.0.1`，并校验请求的 Host 与 Origin，网页上别的站点不能驱动它的接口。没有账号，没有遥测。
- 密钥只写入本机的 `settings.json`，不会被上传，也不会被打包进安装包。
- **但检索和下载必须联网**：你输入的标题、DOI、关键词、作者名，以及你填的联系邮箱，会发给所用到的第三方服务（Crossref、OpenAlex、Unpaywall、Europe PMC 等；启用时还有 Sci-Hub 镜像、出版社网站、ChemRxiv、ChemASAP、百度学术、ResearchGate）。使用前请知晓这一点。
- 机构通道使用你自己的浏览器会话，程序不保存密码。

## 11. 常见问题

**大量「检索失败」或查不到 DOI**：多半是被限流。确认已填联系邮箱；调低并发；分批运行（一次几十条比一次几百条稳定）。

**学校有订阅却下不到**：先在该行点「机构登录」登录一次，再重下。若仍失败，看那一行的说明——「网络慢」和「没有订阅」是两回事，前者重试即可。

**PDF 打开是空白页**：目前除 ⑧ 页的直链外，其它渠道只检查文件头，截断的文件可能漏过。删掉该文件，并在界面里勾「重新下载」再试。

**一直卡在某一篇**：单篇有 240 秒预算，机构浏览器单次等待上限默认 75 秒（设置 `inst_timeout`，5–300 秒）。可先「暂停」，处理完别的再「继续」。

**对话框没有弹出 / 弹出后不在最前**：见 §2，选择器只用 tkinter；报错时直接在输入框里填路径。

**日志**：`%LOCALAPPDATA%\DOIFinder\doifinder.log`（超过 1 MB 轮转）。每批下载结束会逐条记录未下到的文献和原因（以 `miss` 开头的行）。

**界面点按钮没反应**：右上角状态栏会显示脚本错误和行号；Ctrl+F5 刷新通常可解决。
